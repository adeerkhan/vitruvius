Why not just search

A search engine returns snippets

Vitruvius reads the source, records the provision, and hands you a claim you can walk back to a page number.

Reads, never infers

A code provision, a spec value, a material property is read before it is summarised — not inferred from a title, a snippet, or memory.

Never fabricates

Every named standard, product, project and dataset must have a verifiable reference. If none was found, it is not mentioned.

Records provenance

Outputs are intended to ship with a .provenance.md sidecar naming what was checked and how, so a reader can audit rather than trust.

Flags uncertainty

Findings carry a status: verified inferred blocked unverified. Missing checks are never smoothed over.

Is measured

The verifier runs against a scored adversarial benchmark with deterministic controls. The numbers are on this page, including the runs where it was wrong.

Learns deliberately

Habit captures only explicit, user-approved research preferences in a project-local store. It never rewrites agent instructions on its own.

The research loop

Seven phases, every time

Every skill runs the same shared method. The last phase is a gate: the run is not done until an independent check re-derives the original question and finds it answered.

Plan

Questions, evidence, scale decision.

Scale

Direct search, or decompose across agents.

Gather

Open sources, record exact provisions.

Draft

Synthesise with citations as you write.

Cite

Sweep every claim back to its source.

Review

Blind check, eight adversarial tests.

Deliver

Goal-check gate. Output plus provenance.

Known limits

Written down here rather than left to be discovered. Each item is a real gap in the current state of the repository.

  • 01
    Per-case variance is material These are reported measurements, not certification. The decision rule was fixed before the first run and no case or threshold was changed.
  • 02
    A single pressure run was talked into one false approval It held at majority across three runs. Both results are shown above.
  • 03
    Routing misses four prompts out of twenty Rank-1 accuracy, not coverage. The misses are tracked as a regression record.
  • 04
    The baseline comparison is a pilot, not a result One case, flagged shared-harness. It checks the procedure; it does not compare the agent to a plain prompt.
  • 05
    The field pilot has no external-source result Format and refusal tests only. No real pilot record is claimed yet.
  • 06
    Provenance validation is partial The validator covers selected root, plan and draft paths. Nested and method-specific sidecars remain a known gap.
  • 07
    Anchors prove binding, not correctness The problem-anchor contract resolves every path:line against real bytes, but it does not read the claim. An anchor that points at the wrong line still passes.

Grounding

Keeping a report about your problem

A perfectly cited literature review that never opens the codebase it was commissioned about passes every citation check and answers nobody. These rules close that gap, and the mechanical half is a script rather than a plea.

Rules the agent follows

  1. 01
    Name the artifacts before searching The files, repos or documents the run studies, plus the commit. The record hash-pins them, so the hash set is the snapshot.
  2. 02
    Repo claims carry an anchor A claim about the artifact under study resolves to path:line on disk. You cannot assert a codebase lacks something without opening it.
  3. 03
    Every finding names its landing site Change, measure, defer, product-decision or background. A finding with no landing site has to say which it is.
  4. 04
    Every decision gets a position A report may not list a decision and then ignore it.
  5. 05
    Silence is not a finding Record what you searched for, what you did not find, and where the search stopped.
  6. 06
    Weight follows evidence An impact or priority claim states its evidence and the cost of being wrong.

The six non-negotiables

These are the repository contract. An agent that cannot satisfy one reports that it cannot.

  1. 01
    Never fabricate a source Every standard, code, provision, product, material, project or dataset must have a verifiable reference. No reference, no mention.
  2. 02
    Never claim something exists without checking If a search returns zero results, it does not exist. It is not written up anyway.
  3. 03
    Never extrapolate what you have not read An unread source may be noted as existing. Its contents may not be described.
  4. 04
    A reference or it did not happen Standard and section, URL, artifact path, or calculation. One of the four.
  5. 05
    Read before you summarise No inferring a code provision, a spec value or a material property from a title when a direct read is possible.
  6. 06
    Mark status honestly Verified, inferred, blocked, unverified. A missing check is named as missing.

The cast

Separate roles, so nothing grades itself

The verifier, the reviewer and the habit extractor hold no write access. A judge that can edit the evidence it is judging is not a check.

  • researcher

    Evidence gathering. Finds and opens the sources.

  • writer

    Synthesis. Turns read sources into a cited draft.

  • verifier

    Blind verdict on a claim against its evidence. Read-only.

  • reviewer

    Adversarial review. Reports findings, never repairs them.

  • arbiter

    Adjudicates a verifier disagreement. Does not re-research.

  • goal-checker

    Independent end-of-run check. Defaults to not-done.

  • habit

    Preference extraction. Abstains by default, asks before applying.

Questions

The ones that actually come up

How is this different from web search?

Search returns snippets and links. Vitruvius opens the source, records the specific provision it relied on, and returns a claim with a location. Where it could not open the source, it says so instead of paraphrasing the snippet.

What happens when a source is paywalled?

It is cited from search metadata and marked blocked. Its contents are never guessed at. There is a written policy for this in the repository, not just an instruction to the agent.

Which sources count as evidence?

Standards and code bodies first, cited as standard plus section plus edition. Then primary academic literature through keyless APIs. Undated blog posts, aggregators, unattributed forum posts and sources that look machine-generated are rejected outright.

How do I check the agent's claims?

Look for the status label on each finding, and the provenance sidecar beside the output. A blocked label is a real answer, not a failure to be hidden. The validator covering sidecars is itself partial, and the site says so in the limits list above.

Is the benchmark a certification?

No. It is a scored set of cases with known control and variance limits, published with its residuals. The certified figures use a majority of three independent runs under a rule fixed before the first run; per-case variance is still material.

Can it be used outside engineering?

The loop is general; the evidence landscapes are not. Two skills work in any field with academic literature because they depend only on those sources, but the discipline skills assume engineering standards and codes exist and matter.
