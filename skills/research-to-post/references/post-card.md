# Post Card and Media

The post card is the delivery surface. It shows the ready-to-paste post, the
chosen media, the claim ledger, and the verification summary in one
self-contained HTML file. It is generated by
`scripts/render-post-card.mjs`; do not hand-write the HTML.

The card is a preview, not a publication step. Nothing in this workflow posts,
schedules, or scrapes.

## Choosing the media

Pick the visual that carries the same claim as the hook. Work down this list and
take the first option the evidence supports:

| Order | Media | Use when | What the card needs |
|-------|-------|----------|---------------------|
| 1 | `figure` | The source has a key figure or table image that *is* the claim, and its license is checked | `path`, `alt`, `caption`, `credit`, `license`, `licenseChecked: true` |
| 2 | `chart` | The claim is a number with a baseline, and the source gives both | `chart.data` where every point names a `claim` id and matches its value |
| 3 | `text` | The claim is qualitative, or a number reads better as one line than as a chart | `text`, `alt`, `credit` |
| 4 | `video` | A 15-30 s storyboard explains the mechanism or the before/after better than a still | `video.shots` with time, visual, and on-screen text |
| 5 | `none` | No visual can be made honestly | `alt` still required for the card summary |

Rules:

- **Same claim, same number.** The media must show the number the hook shows,
  with the same unit and baseline. A beautiful chart of a different metric is a
  different post.
- **No stock photos as evidence.** A stock image may illustrate a mechanism only
  when the card labels it `illustration`, never as a result or a measurement.
- **No generated data visuals.** Do not use an image generator to draw a chart,
  a table, or a figure that looks like the paper's. Generate the chart from the
  ledger with the script, or use the source figure with credit.
- **License before embed.** A figure is embedded only when the user has checked
  its license. Otherwise describe it and recommend recreating it.
- **Alt text is part of the post.** It states what the visual shows, including
  the number and its baseline, for a reader who cannot see it.
- **X aspect ratio.** Prefer 16:9 (1200 x 675) for a single image or video
  frame. Keep text away from the outer 5% so a crop does not remove it.
- **Sound off.** A video must make sense muted: every claim appears as on-screen
  text, and the caption repeats the number.
- **Virality is not a guarantee.** The card optimizes clarity, a concrete
  number, and a shareable visual. It cannot promise reach, and no field in the
  card claims a predicted performance.

### Finding the most relevant figure

Start from the angle and the claim's `source_location`, not from what looks
good:

| Angle | The visual that fits |
|-------|----------------------|
| Result-first | The results table or figure the number comes from, or a bar chart of result vs baseline |
| Counterintuitive finding | The before/after result, with both the expected and observed values |
| Builder's takeaway | The decision variable and its range, not the full paper figure |
| Plain-language explainer | A mechanism schematic or a labelled diagram, credited |
| "What the paper doesn't say" | The scope table or the tested-condition matrix |
| Replication or extension (yours) | Your run's plot, labelled as your work |
| Open question | The result figure plus the open question as a caption |

How to get it:

1. Open the source at the cited page/table/figure and confirm the visual carries
   the claim. Do not use a figure from a different section.
2. If the source is a PDF you can read, export the figure with its caption at a
   readable resolution and save it to `outputs/<slug>-figure.png`. Crop only
   whitespace; never redraw the data.
3. If the license is unclear or the figure cannot be exported, use the ledger
   chart or describe the figure in text. A missing image is better than an
   unlicensed one.
4. If the source is open access, keep the figure credit and the license line in
   the post card, and link the source in the final post.


## Card input JSON

Save the input to `outputs/.drafts/<slug>-post-card.json`. The script validates
it and fails closed on any inconsistency.

```json
{
  "slug": "steel-brace-connection",
  "title": "Steel brace connection",
  "source": {
    "citation": "Author et al., Journal, 2026",
    "url": "https://doi.org/10.0000/example",
    "commit": null
  },
  "format": "thread",
  "limit": 280,
  "angle": "Result-first",
  "angle_reason": "The paper reports one strong, directly comparable number.",
  "hooks": [
    { "text": "Hook A ...", "recommended": true },
    { "text": "Hook B ...", "recommended": false },
    { "text": "Hook C ...", "recommended": false }
  ],
  "post": [
    { "text": "The brace reached 18% drift capacity, against 12% for the baseline.", "claims": ["C1"] },
    { "text": "The gain comes from ...", "claims": ["C2"] }
  ],
  "claims": [
    {
      "id": "C1",
      "claim": "Drift capacity of the braced frame",
      "value": "18",
      "unit": "%",
      "baseline": "12%",
      "source_location": "Table 3, p. 9",
      "status": "verified",
      "used": true
    }
  ],
  "media": {
    "kind": "chart",
    "why": "The hook is the drift comparison, so the chart shows both bars.",
    "alt": "Bar chart: baseline 12% drift capacity, braced frame 18%.",
    "caption": "Drift capacity at the same drift limit, Table 3.",
    "credit": "Chart built from Table 3.",
    "chart": {
      "type": "bar",
      "title": "Drift capacity",
      "unit": "%",
      "data": [
        { "label": "Baseline", "value": 12, "claim": "C1", "role": "baseline" },
        { "label": "Braced frame", "value": 18, "claim": "C1" }
      ]
    }
  },
  "verification": {
    "verified": 1,
    "partial": 0,
    "blocked": 0,
    "checked_by": "lead agent (no verifier subagent available)",
    "notes": "Table 3 read directly; limitation is stated in post 3."
  }
}
```

For a source figure, replace `media` with:

```json
"media": {
  "kind": "figure",
  "why": "Figure 4 is the load-displacement curve the claim refers to.",
  "alt": "Load-displacement curve ...",
  "caption": "Figure 4, Author et al.",
  "credit": "Figure 4, Author et al., reproduced with permission.",
  "license": "CC BY 4.0",
  "licenseChecked": true,
  "figure": { "path": "outputs/<slug>-figure.png" }
}
```

For a text card:

```json
"media": {
  "kind": "text",
  "why": "The claim is a condition, not a number, so one line reads better than a chart.",
  "alt": "Text card: the result holds for the tested frame only.",
  "caption": "Scope condition from Section 4.2.",
  "credit": "Text card built from Section 4.2.",
  "text": "The result holds for the tested frame only."
}
```

For a video storyboard:

```json
"media": {
  "kind": "video",
  "why": "A 20 s before/after shows the mechanism better than one still.",
  "alt": "Storyboard: baseline frame, braced frame, caveat, source.",
  "caption": "Drift capacity comparison, Table 3.",
  "credit": "Storyboard by the author.",
  "video": {
    "duration_s": 20,
    "shots": [
      { "t": "0-4s", "visual": "Baseline bar at 12%", "text": "Baseline: 12% drift" },
      { "t": "4-10s", "visual": "Braced bar at 18%", "text": "Braced: 18% drift" },
      { "t": "10-16s", "visual": "Table 3 excerpt", "text": "Same drift limit, Table 3" },
      { "t": "16-20s", "visual": "Source card", "text": "Author et al., 2026" }
    ]
  }
}
```

## What the script refuses

The render exits non-zero, names the problem, and writes no card when:

- a `used` claim is not `verified` or `partial`, or a `partial` claim has no
  `qualifier`;
- a post references a claim id that is not in the ledger;
- a `used` claim is not referenced by any post;
- a chart point names a missing claim, a claim that is not `used`, or a value
  that does not match that claim's numeric `value` (or its `baseline` when the
  point sets `role: "baseline"`);
- a figure is missing `alt`, `credit`, `license`, or `licenseChecked: true`;
- a text card has no `text` line;
- a figure path is absolute, escapes the project, or does not exist;
- a post exceeds the character limit, or a `thread` has fewer than 4 or more
  than 7 posts;
- the `verification` counts disagree with the ledger statuses;
- `slug` is not lowercase-hyphen-separated.

## CLI

```bash
node skills/research-to-post/scripts/render-post-card.mjs --input <json> --output <html>
node skills/research-to-post/scripts/render-post-card.mjs --input <json> --check
```

`--check` validates only. The HTML is self-contained: inline CSS, inline SVG
chart, no remote fonts, scripts, images, or analytics. A copy button is the only
behaviour, plus the chart's "Download chart as PNG" button (rendered at
1200 x 675, 16:9) and the figure's download link so the user has a postable
image. A video is a storyboard, not a generated file.
