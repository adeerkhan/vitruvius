# Post Hooks

A hook is the first line a reader sees. It earns attention with specificity,
not volume. These are structural patterns written for this skill; they contain
no copied posts. Fill the brackets from the claim ledger only.

## Shapes that work

| Shape | Pattern | Use when | Honesty guard |
|-------|---------|----------|---------------|
| Number first | "[N units] [outcome] with [constraint]." | One strong, verified number | The baseline appears in the same post, not only the thread |
| Contrast | "[Common belief]. [This result] says otherwise: [number]." | The paper or a cited work states the belief | Quote the belief from a source, not from impression |
| Constraint | "[Result] using only [small resource]." | The efficiency or cost claim is the finding | State the resource figure with units |
| Plain question | "Why does [observed behavior] happen? A new paper answers it." | The paper actually answers the question | The post must deliver the answer, not stall |
| Failure report | "I tried [method] on [task]. It broke at [condition]." | Your own replication or extension | Say what you ran and with what code |
| Scope check | "[Result] holds for [conditions]. Here is what is not shown." | A strong result with narrow scope | Take the scope from the methods section |
| Before and after | "[Old way: number] to [new way: number]." | Both numbers come from the same source and setup | Same hardware, dataset, and metric on both sides |

## Rules for the first post

- Lead with the concrete thing: a number, a mechanism, a condition, or a real
  question. A first line that could open any post is the wrong first line.
- One idea. Cut the second claim into the thread.
- Plain nouns and verbs over adjectives. If an adjective carries the claim
  ("dramatic", "huge"), replace it with the number.
- No link in the first post.
- Read it aloud as a skeptical expert in the field. If they would ask "compared
  to what?", add the baseline.

## Words that need evidence before they appear

State-of-the-art, first, only, best, outperforms, breakthrough, solves, proves,
beats, "game-changer". Each needs a ledger row that supports it
(for example, a results table showing the comparison) or it is cut. "Shows" and
"proves" need stronger evidence than "suggests" and "finds"; match the paper's
own verb.

## What travels, without overclaiming

- **Specificity.** A concrete number with its baseline is more shareable than an
  adjective. "18% vs 12%" travels; "much better" does not.
- **A true surprise.** The contrast is only a surprise if a cited source states
  the expectation. Otherwise it is a claim the reader cannot check.
- **A visual that carries the claim.** A figure or chart that shows the same
  number as the hook is what a reader screenshots. Decorative imagery is not.
- **Utility.** A builder's takeaway or a scope check gives the reader something
  to do or to avoid. It must be labelled as inference when it is yours.
- **One idea per post.** A thread that adds a new ledger claim per post is read
  to the end; padding is not.

These are structural patterns, not measured effects. The skill does not promise
virality, and it never trades accuracy for reach.

## Thread shape (4-7 posts)

1. Hook — the single strongest verified claim.
2. The result — number, units, baseline, figure.
3. How it works — the mechanism in plain words (one analogy, flagged if lossy).
4. The limitation — scope, caveat, or what is not shown.
5. So what — the decision or question this changes for the reader.
6. Source — link, authors, and figure credit.

Add a post only when it carries a new claim from the ledger. A thread padded to
reach a length is worse than a short one.
