# Q1 Evidence Ledger Contract

`evidence.v1` is a local-only, per-run JSON document. The writer requires an
existing L1 `run.v1` entry and refuses overwrite. It uses the shared
`.log-run.lock` protocol.

## Root fields

- `schema`: exactly `evidence.v1`
- `run_id`: the existing L1 UUID
- `question`: the bounded research question
- `sources`: one or more source records
- `searches`: one or more search records
- `claims`: one or more claim records
- `coverage`: `negative` and `ambiguous` arrays
- `recorded_at` and `completion`: generated by the writer; completion is
  `complete`, `partial`, or `blocked`

## Source records

Each source has `id`, `title`, `locator`, `artifact_path`, `sha256`,
`accessed_on`, `status`, and optional `notes`. `artifact_path` is a confined
repository-relative regular file and its bytes must match `sha256`. The Q1
pilot is local-only; a blocked external source is represented by a local block
record, not a guessed external document.

## Search records

Each search has `id`, `query`, `boundary`, `searched_on`, `status`,
`screened_count`, and `result_source_ids`. Completed/partial searches carry a
non-negative integer count; blocked searches carry `null`. Every source must be
linked by a search result. Every search needs a negative-coverage record.

## Claims and coverage

Each claim has `id`, `text`, `status`, `coverage_status`, and non-empty
`support`. Each support mapping has `source_id`, `locator`, `relation`, and
`status`. A verified claim needs verified support and cannot be covered while
an open ambiguity or negative coverage exists. Negative and ambiguous entries
carry `id`, `search_id`, `claim_ids`, `status`, and `note`.

Unknown/duplicate IDs, orphan mappings, byte/hash mismatches, missing negative
coverage, unlinked support, and contradictory coverage fail closed. A negative
entry may have an empty `claim_ids` list when it records a search-level boundary;
when populated, those IDs must be real claims. A valid partial or blocked ledger
is retained with non-complete completion; it is not reported as a completed
claim set.

## Commands

```bash
printf '%s\n' '<evidence_json>' \
  | node <engineering-research-skill-root>/scripts/record-evidence.mjs --run-id <run_id>
node scripts/validate-evidence.mjs .runs/<run_id>.evidence.json
```

The repository wrappers are `scripts/record-evidence.mjs` and
`scripts/validate-evidence.mjs`. The skill-local scripts are self-contained for
copied-skill installations.
