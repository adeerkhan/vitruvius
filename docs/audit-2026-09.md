## 1. Verdict Summary

**The moat is real but unmeasured.** Vitruvius's differentiator — independent
blind verification with BLOCKED as a legitimate outcome — exists nowhere in
the reference repos in this form. But the verifier's actual catch rate has
never been scored: `tasks/benchmark/results/` is empty while
`tasks/benchmark/cases/` holds 20 adversarial cases (4 flaw types × 5
disciplines). We claim "independent verification" (STEAL.md A1–A3, marked
done) without a single recorded benchmark run. That is the same
breadth-without-proof weakness we criticize Scientific Agent Skills for.

**Second finding: independence is violated by construction.** The blind
verifier ships with `allowed-tools: Write Edit Bash Read`
(`skills/verifier/SKILL.md:12`). A verifier that can edit is a verifier that
can quietly "fix" the artifact it is judging instead of reporting on it.
Autoprompt's juror has no Edit tool and states "you MUST NOT edit production
code" (`ref/autoprompt-skill/agents/claude/agents/ap-juror.md:4,17`).

**Third finding: one shipped skill dispatches a skill that does not exist.**
`skills/proposal/SKILL.md:9,229,312` references `/humanizer` as an isolated
subagent. Humanizer is a reference repo in `ref/`, not a shipped skill
(`skills/` has 24 entries; none is humanizer). The proposal skill also
requires `voice-sample.txt` (`proposal/SKILL.md:92`) — an asset with no
counterpart in the repo. The contract validator checks that local file links
resolve but does not check skill-name references, so this shipped silently.

## 3. Critical Defects (ranked by severity)

### D1 — The moat is unmeasured (CRITICAL)

- `tasks/benchmark/results/` is **empty**. 20 cases exist; zero scored runs.
- `tests/verifier/test-verifier.mjs:5` asserts "no false approvals (verifier
  PASS on BLOCKED case)" and "≥80% correct verdicts (13/16)" — but with no
  results on disk these assertions pass vacuously by skipping scoring.
- Consequence: every "verification" claim in README/STEAL.md is unbacked by
  our own integrity standard. "A reference or it didn't happen" applies to us.

### D2 — Verifier can edit what it verifies (CRITICAL)

- `skills/verifier/SKILL.md:12`: `allowed-tools: Write Edit Bash Read`.
- Roles are prose inside SKILL.md files, not dispatchable agent definitions
  with tool boundaries. Autoprompt solves this with standalone agent files
  (`agents/claude/agents/ap-*.md`) carrying per-agent `tools:` frontmatter,
  a ≤150-word report shape, and an INVALID-DISPATCH/no-recursion contract.
- We have no agent files at all: researcher/writer/verifier/reviewer/arbiter
  live as sections inside `engineering-research/SKILL.md`. The A4 arbiter
  flow (`engineering-research/SKILL.md:320-334`) is prose only — nothing
  dispatches it, nothing tests it.

### D3 — Broken skill reference shipped (HIGH)

- `skills/proposal/SKILL.md:9` — "Wraps /gap-analysis, /evidence-ranking,
  /verifier, and /humanizer as isolated subagents." No humanizer skill exists.
- `proposal/SKILL.md:229` — "Dispatch `/humanizer`" — unresolvable at runtime.
- Contract validator gap: `scripts/validate-contract.mjs` validates local
  file paths, not cross-skill references. Add a lint: every skill name
  mentioned as `/skill-name` in any SKILL.md must exist in `skills/`.

### D4 — Provenance is prose, not data (HIGH)

- F2's 6-label system is documented (`engineering-research/SKILL.md:434-443`)
  and sidecars are markdown. Nothing validates them.
- Historical Feynman comparison (not a current pinned source): an earlier
  Feynman revision had a `feynman.researchRun.v1` manifest schema and validator
  (historical path `ref/feynman/src/research/contracts.ts:103-133,167-193`).
  That path is absent from the current checked-out Feynman revision, so this
  citation is retained only as historical evidence, not a current source claim.
  Ours: `scripts/log-run.mjs` appends JSON but no schema check on the sidecar
  itself.
- Consequence: "auditable provenance" is a convention, not a guarantee. A
  sidecar missing `Claims verified:` counts would pass CI today.

### D5 — Tests verify structure, not behavior (HIGH)

- The test chain (`package.json:42`) checks frontmatter, links, artifact
  shape, security patterns. Good hygiene, zero behavioral signal.
- Agent-skills runs a 3-tier eval system (`ref/agent-skills/evals/README.md`):
  Tier 1 structural lint; Tier 2 trigger-routing evals (TF-IDF rank-1 floor
  of 95%, pairwise description-collision error at ≥75%); Tier 3 headless
  behavioral runs with `expectations[]` graded from execution traces,
  including pressure cases. We have Tier 1 only, and no way to know whether
  "/verify this beam" routes to `civil` or `mechanical` or neither.
- With 24 skills, description collisions are unmeasured.

### D6 — Verifier missing two cheap, high-value checks (MEDIUM)

- **No orphan-source rule.** Feynman's verifier requires BOTH no orphan
  citations AND no orphan sources — every listed source must be cited
  somewhere, every citation must map to a listed source
  (`ref/feynman/.feynman/agents/verifier.md:26-27`). Ours pins
  claim→source but never checks the reverse.
- **No result provenance audit.** Feynman sweeps the draft for
  numbers/benchmarks/figures and removes or TODOs anything without a
  traceable artifact (`verifier.md:44-54`). Our Step 6.5 audit
  (`engineering-research/SKILL.md:364-390`) covers claims but not
  figures/tables as artifacts.

### D7 — Repo hygiene issues (MEDIUM)

- `tests/` contains research artifacts that are not tests:
  `provenance-test1.md`, `provenance-test2.md`, `provenance-test3.md`,
  `civil-deep-dive-tests.md`, `test-1-mechanical-deep-report.md`,
  `INTEGRATION-TEST-FINAL-REPORT.md`, `VITRUVIUS-EVALUATION-REPORT.md`, etc.
  Sci Agent Skills enforces "no stray tests" — tests live in
  `tests/<skill-name>/` and nothing else.
- No per-skill versioning. Sci Agent Skills requires `metadata.version` on
  every skill and bump-on-change discipline (their AGENTS.md). We can't tell
  which skills changed since a user installed.

### D8 — Zero adoption surface (MEDIUM)

- README has no badges, no quantified claim, no demo, no worked example.
  STEAL.md itself tracks this (R1–R12, all planned) — but every R-item is
  downstream of D1: you cannot lead with "independent verification" until a
  benchmark number exists to lead with.
- No worked-examples doc. Sci Agent Skills ships 45 end-to-end prompted
  examples (`docs/examples.md`, 6600+ lines) ending in a failure-mode
  anthology. We ship zero. A prospect cannot see what a run looks like
  without installing.

### D9 — Escalation and fan-out are untested design (LOW-MEDIUM)

- A4 conditional escalation (1→2→3 verifiers) and the T2 parallel fan-out
  (`engineering-research/SKILL.md:150-178`) exist only as prose. No test
  exercises disagreement handling, and the fan-out skip criteria are not
  enumerated (agent-skills documents explicit fan-out skip criteria in
  `.claude/commands/ship.md:66-72`).

## 5. What We Are Doing Wrong (honest mistakes)

1. **Claiming done without on-disk proof.** STEAL.md marks A1–A3 "done" while
   the arbiter is undispatchable prose and the benchmark is unscored. Our own
   AGENTS.md rule ("Never claim a fix or a check landed unless an explicit
   on-disk verification proves it") was applied to everyone but ourselves.
2. **Building scaffolding instead of running it.** The benchmark framework
   (cases, parser, scorer, thresholds) is complete. It has never been fed a
   single verifier output.
3. **Verifying structure and calling it quality.** Contract tests are
   necessary and insufficient. A skill can pass every structural check and
   still fail at its one job.
4. **No distribution surface.** The repo is invisible: no badges, no numbers,
   no examples. For a project whose pitch is trust, trust is exactly what the
   README fails to demonstrate.
5. **Validator blind spots.** The contract lint checks files, not
   references between skills (D3), and not provenance completeness (D4).
6. **Workspace pollution.** `tests/` doubles as a dumping ground for research
   runs, which makes the test suite look more impressive than it is and
   breaks the "no stray tests" discipline.

## 7. What Makes Vitruvius Grand (the unique position, stated precisely)

No reference repo — and nothing we found in the wider skills ecosystem —
combines:

1. **Domain adversarial verification** — a verifier trained-by-prompt on
   engineering failure modes (unit errors, omitted load combinations,
   resistance-factor misuse, standard conflicts) with a scored, falsifiable
   benchmark.
2. **BLOCKED as a first-class verdict** — the engineering sign-off culture:
   "unverifiable" is an honest output, not a failure to be papered over.
3. **Machine-checked provenance** — every claim line-pinned, every sidecar
   schema-validated in CI, every benchmark result published.

The grand version of Vitruvius is not more skills. It is the only research
agent whose verification claims are themselves verified — with published
numbers. Everything in §6 serves that single sentence.
